# LAB - CloudOps / Azure workspace

A local, git-friendly workspace for Azure, Microsoft 365, Intune, security and IT
operations work. It is organised so that you, your colleagues and an AI coding agent
(Claude Code or similar) find things in the same place, follow the same rules and leave
a trail that someone else can pick up.

It was generated by [Vorterm](https://github.com/4leX-42/Vorterm7.0). From now on it is
yours: rename, delete or add areas freely. Nothing here connects to any tenant or
subscription until you decide to.

## Layout

| Folder | What goes there |
| :-- | :-- |
| `Azure/` | Subscriptions, resources, networking, identity for workloads, cost. Scripts and IaC. |
| `Microsoft365/` | Entra ID, users, groups, licensing, SharePoint, Teams, Microsoft Graph. |
| `Outlook/` | Exchange Online, mailboxes, mail flow, Outlook client troubleshooting. |
| `Intune/` | Devices, compliance, configuration profiles, apps, Autopilot. |
| `Cybersecurity/` | Incidents, hunting queries, hardening baselines, detection notes. |
| `PowerAutomate/` | Flow documentation, exported definitions, connectors and integrations. |
| `CloudOps/` | Runbooks, monitoring, recurring operations, troubleshooting guides. |
| `PowerShell/` | Shared modules and functions, generic scripts and their tests. |
| `DevOps/` | Pipelines, Git conventions, containers. |
| `Documentation/` | Decisions (ADR), procedures, reports, architecture notes. |
| `Templates/` | Runbook, change plan, incident, postmortem, project, script and query templates. |
| `Tools/` | Helpers for the LAB itself: create items from templates, validate scripts. |
| `config/` | Local configuration. Only `*.example.*` files are committed. |
| `exports/`, `logs/`, `evidence/` | Generated data. Ignored by git; see each README. |

Every area has a `README.md`. Areas with rules of their own also have a `CLAUDE.md`.

## How work flows here

1. **Read before you write.** Check the real state first (who, what, how many) with
   read-only commands.
2. **Plan.** For anything that changes a system, fill in `Templates/change-plan.md`:
   what, scope with a count, risks, what cannot be undone, rollback.
3. **Dry run.** Write scripts are dry-run by default and need `-Execute` to apply.
4. **Execute** only what the plan says. Anything new means stop and re-plan.
5. **Verify** by reading the result back. "No error" is not proof.
6. **Record** what happened: runbook, incident file, decision record or TODO.

## Quick start

```powershell
# New runbook, incident, change plan or project from a template
.\Tools\New-LabItem.ps1 -Type runbook  -Area CloudOps      -Title 'Rotate storage keys'
.\Tools\New-LabItem.ps1 -Type incident -Area Cybersecurity -Title 'Suspicious sign-in'
.\Tools\New-LabItem.ps1 -Type project  -Area Azure         -Title 'Landing zone review'

# Check every script in the LAB (syntax on PowerShell 5.1 and 7, ASCII, header)
.\Tools\Test-LabScripts.ps1
```

If PowerShell blocks the scripts, see "Execution policy" in `Tools/README.md`.

## Data, secrets and evidence

- Never commit secrets, certificates, tokens, `.env` files or real exports. The
  `.gitignore` already excludes the usual suspects; check `git status` before every commit.
- Real data goes to `exports/`, `logs/` or `evidence/` (all ignored). Documents reference
  the path and a summary, never a raw dump.
- Placeholders use reserved values: `contoso.example`, `00000000-0000-0000-0000-000000000000`,
  `user@contoso.example`.

## Working with Claude Code

`CLAUDE.md` holds the rules every session follows; area `CLAUDE.md` files add the rules that
only apply there. `.claude/` contains project settings (secret files are unreadable, risky
cloud and git commands ask first), two subagents (read-only auditor, script reviewer) and
three skills (`new-script`, `change-plan`, `incident`).

Nothing assumes a particular plugin or MCP server. `LAB-INVENTORY.md` lists the optional
tools that fit this layout and how to enable them.

## Keeping the LAB up to date

Run Vorterm again (or `lab\New-VortermLab.ps1` from the Vorterm folder) pointing to the
same parent folder. Missing files are added; files you have not edited are refreshed;
files you changed are kept as they are and listed as "kept". Nothing is deleted.
`.vorterm-lab.json` records which template version you have.
